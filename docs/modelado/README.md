# Modelado

Este espacio conecta las necesidades del proyecto con los modelos que implementarán frontend, backend y base de datos.

## Debe publicarse aquí

- alcance y actores del sistema;
- historias de usuario y criterios de aceptación;
- casos de uso y flujos principales;
- modelo de dominio, estados y reglas del negocio;
- diagramas de secuencia o actividad cuando aclaren un comportamiento;
- trazabilidad entre requisito, historia, endpoint, pantalla y entidad;
- supuestos, decisiones pendientes y preguntas abiertas.

Una historia debe ser verificable y enlazar sus criterios de aceptación. Los diagramas de tablas se detallan en `base-de-datos/`; las decisiones de integración se enlazan desde `arquitectura/`.

## Estado

- Pendiente: publicar historias, criterios de aceptación y modelo de dominio.
